# 合成小红帽 · 4Ward 学生节

纯前端合成小游戏。入口为 `merge.html`，业务代码、样式和类型位于 `src/merge/`。不需要 npm、不需要安装依赖、不需要联网，也不需要启动服务器。物理库已经作为本地文件随游戏提供。

## 运行

主页为 `index.html`，包含游戏介绍和进入 `merge.html` 的链接；样式在 `src/home/styles.css`。直接双击主页即可浏览，也可以从游戏左上角的 4Ward 标识返回主页。

**直接双击 `merge.html`。** 请保留整个文件夹结构，不要只复制 HTML。

也可以把 `merge.html`、`src/merge/`、`config/merge/`、`assets/stickers/`、`assets/merge/pop.mp3`、`assets/merge/pop2.mp3`、`assets/merge/drop-soft.wav` 放到已有的静态网站，和其他小游戏共用同一个网站服务；本游戏没有独立服务、端口或后端。手机可以通过这个已有网站游玩。手机系统的文件预览器不一定允许运行 JavaScript，浏览器访问网站是更通用的手机入口。

桌面移动鼠标瞄准、点击放下；手机拖动瞄准、松手放下。键盘左右键瞄准，空格/回车放下，P 暂停。切换到后台自动暂停，返回后手动继续。

## 手机加载与音效

在线访问由 `src/merge/boot.js` 加载游戏脚本，不下载离线包；仅在双击 file:// 模式先加载 `offline-data.js`。当前在线首次进入游戏资源约 4.2 MB（未计 HTTP 压缩及缓存），图片和音频不会再同时以独立文件和 Base64 离线包下载。部署时仍需保留 boot.js、game.js 和素材；发布新脚本时更新 HTML 中的版本查询参数，boot 会将它传递给后续脚本，避免手机继续使用旧缓存。

配置、音频和图片加载最多自动尝试 3 次，每次超时 15 秒，重试分别等待 350 / 700 毫秒；图片逐张加载和处理，并及时释放临时 Canvas，降低手机内存峰值。图片使用加载完成事件，不依赖可能拒绝的 decode() Promise。最终失败会保留重试提示；不改变图片像素或碰撞轮廓精度。

音频在 pointerup、touchend、click 和键盘等手势中尝试解锁。即使前一次 resume() 一直挂起，新的有效手势仍会再次调用，避免 iPhone Safari 永久无声；下载失败的音频保留 3 秒冷却后可在下次手势中重试，已成功解码的音频继续复用。正常触摸游戏区域或点击操作按钮即可触发音频解锁及缺失音频重试。iPhone 若仍听不到，请关闭静音模式并调高音量；页面无法判断扬声器是否真正发出了声音。

## 胜利与领奖

默认共九阶，最后一阶使用 `assets/stickers/grown1.png`。合成第九阶后显示领奖弹窗：**“你合成了小红帽！将此页面展示给工作人员以获取奖励”**。弹窗打开时停止投放，背景保留短暂合成余波，随后定格，玩家可向工作人员展示。点击“继续游戏”关闭弹窗，保留当前贴纸、分数与待投放物品并继续游玩；每局只弹出一次领奖提示。两个最高阶贴纸相碰不会继续合成，之后仍可能因堆叠越线失败。Esc 和点击背景不会关闭领奖弹窗；顶部“重新开始”或刷新页面会重置游戏。

页面标题和游戏名称为“合成小红帽”，活动品牌为 **4Ward**。下一项预览与成长路线仅展示图片和通用阶数，不展示图片名称。

## 皮肤与参数

默认配置：`config/merge/default.json`。

- **双击运行时**：浏览器禁止网页自动读取相邻的 JSON 文件，所以使用 `src/merge/offline-data.js` 中随包附带的默认皮肤数据。它由原始 JSON、PNG 和音频素材生成，不是另一份需要手动维护的配置。
- **修改参数或换皮肤时**：编辑默认 JSON 及其 PNG 路径后重新打包。网站也支持通过 `merge.html?skin=配置文件路径` 加载另一套 JSON；双击模式使用已打包的默认皮肤。页面不提供文件选择入口。
- **放在已有网站上时**：仍直接读取原始 JSON，修改后刷新生效；`merge.html?skin=./config/merge/another.json` 可以选择其他皮肤。图片路径相对于 JSON 所在目录，跨域图片需要 CORS。
- **要把修改后的 JSON/PNG 设为双击默认值**：开发者运行一次 `python scripts/package_merge.py`，更新离线包即可。这个脚本只用 Python 标准库，无需安装第三方包；玩游戏的人不需要 Python。

所有图片和碰撞体加载完成后才开始游戏。导入非法 JSON 或缺失图片会显示错误，并保留原来的游戏。

## 先按想要的手感选参数

物理手感分成三层：`physics` 控制刚体的下落、滑动和碰撞回弹；`jelly` 控制图案和碰撞箱的压缩、拉伸；`mergeBurst` 控制合成瞬间把附近物体弹开的效果。改变其中一层，不等于改变另外两层。

下面的数值是小幅试调的起点，不是保证适合所有皮肤的预设。每次只改一组，导入 JSON 后用相同摆法比较。

| 想要的效果 | 优先调整 | 配合观察 |
| --- | --- | --- |
| 下落更快、更有重量感 | `physics.gravity` 从 22 试到 26 | 如经常触及 `physics.maxSpeed`，重力再大也不会明显加速；速度过高更容易穿透薄轮廓 |
| 普通落地更弹 | `physics.restitution` 从 0.42 试到 0.5 | 保留 `physics.bounceThreshold`，否则很轻的接触也会反复弹；这不是果冻变形幅度 |
| 变形更明显 | `jelly.impactGain` 从 0.5 小幅提高；合成形变由 `mergeBurst.strainKick` 控制 | 只提高上限不会主动产生更大形变；变形会改变真实碰撞箱，并推挤邻居 |
| 果冻回弹更快 | 小幅提高 `jelly.stiffness` | 刚度过高、阻尼过小会增加抖动；不要直接调到校验上限 |
| 果冻晃动更久 | 小幅降低 `jelly.damping`，例如 8 → 7 | 更容易持续挤动；想尽快安静则反向调整 |
| 合成时弹得更远 | `mergeBurst.speed` 从 14 试到 16 | 看 `physics.maxSpeed` 是否截断速度，以及是否频繁越过警戒线 |
| 合成波及更多物体 | 提高 `mergeBurst.rangeMultiplier` 或 `mergeBurst.rangePadding` | 不仅扩大范围，同一位置的距离衰减也变小，所以可能同时显得更有力 |
| 合成更偏向往上弹 | 提高 `mergeBurst.upwardBias` | 它调整方向，不直接增加速度；太大会把侧向扩散变成集体上跳 |
| 物体更容易滑动 | 降低 `physics.friction`，必要时同时降低 `physics.frictionStatic` | 静摩擦还与另一接触物体的参数共同作用 |
| 更快停稳、减少微小抖动 | 先提高 `jelly.damping` 或 `physics.bounceThreshold`，必要时略增 `jelly.restDeadband` | `restResponse` 越大越快追随支撑变化；`sleepFrames` 越小越早休眠，但可能过早“定住” |
| 更像硬物 | `jelly.enabled: false` | 刚体碰撞、重力和合成冲量仍会工作 |
| 手机更流畅 | 先把 `rendering.maxDpr` 从 2 降到 1.5、减少粒子；物理压力大再降低轮廓精度 | `collision.resolution` 48 → 40 会改变碰撞形状；减少迭代次数则可能损害堆叠稳定性 |

**建议的试调顺序**：先调下落与刚体回弹，再调果冻，最后调合成冲量。保留一份原 JSON；用 `merge.html?debug=1` 观察真实碰撞轮廓（粉色活动、蓝色休眠）。检查单个物体落地、两物体相撞、多物体堆叠、连续合成这四种情形。

## JSON 全部参数说明

下表默认值对应 `config/merge/default.json`，不是缺字段时自动补齐的全部默认值。大多数字段必须保留；只有本文最后列出的兼容字段允许省略。范围来自 `src/merge/config.js` 的校验，**能通过校验不代表极端值也稳定或好玩**。JSON 不允许注释、尾随逗号；布尔值写 `true` / `false`，数字不要加引号。

### 单位与坐标

- 容器左上角是 `(0, 0)`，x 向右、y 向下。下文用 **U** 表示逻辑长度单位，**s** 表示秒。
- 默认容器宽 10 U、高 15 U，比例为 2:3；这是中央容器的比例，不是整个网页的比例。窗口缩放只改变显示倍率，世界大小、物体比例和警戒线相对位置不变。
- `items[].size`、警戒线和出生位置等使用 U；速度使用 U/s；重力使用 U/s²。PNG 原始像素和屏幕 DPR 不决定物体的逻辑尺寸。
- `physics.unitsPerWorldUnit` 是逻辑单位到 Matter.js 内部单位的换算，不是屏幕像素倍率。普通调手感时保留 100。
- 投放冷却、越线计时、胜利余波等按模拟时间计算；暂停时停止。严重掉帧时主循环会丢弃多余积累时间，模拟时间可能落后于现实时间。

### 根字段

| 参数 | 默认值 / 约束 | 运作方式 |
| --- | --- | --- |
| `version` | `1`，目前只能为 1 | 配置格式版本；不是游戏难度或物品等级 |
| `name` | `合成小红帽`；非空字符串 | 皮肤配置标识；参与最高分的本地存储键（4Ward 前缀），改名会使用另一份最高分记录。游戏界面名称固定为“合成小红帽” |
| `items` | 9 项；数量必须等于 `rules.n` | 按阶数从小到大排列的配置数组；合成目标为下一项，最后一项为胜利目标 |

### 容器 `world`

| 参数 | 默认值 | 单位 / 校验范围 | 运作方式与调节影响 |
| --- | --- | --- | --- |
| `world.width` | 10 | U；2–100 | 容器内部宽度；与 height 一起决定固定比例。增加后，物品 size 不变时相对显得更小，可横向容纳更多物品 |
| `world.height` | 18 | U；width–200 | 内部高度；增加后有更多堆放空间，也会改变可用下落距离 |
| `world.dangerY` | 2.6 | U；0.1–height | 警戒线距顶部的位置；值越小线越高，允许堆得更高；值越大通常更容易越线 |
| `world.spawnY` | 1.7 | U；0–dangerY | 预览和投放物体的质心 y 坐标。越小出生越高。还必须满足前 m 阶中最大 size / 2 ≤ spawnY 的校验 |
| `world.wallThickness` | 0.6 | U；0.1–width | 左、右、底部静态墙体向容器外延伸的厚度；内侧边界仍是 x=0、x=width、y=height。不是可见边框宽度，也不缩小内部空间；不要过薄 |

没有顶部刚体墙。越线判定使用碰撞体包围盒顶部，而不是物体中心或 PNG 完整矩形。

### 玩法 `rules`

| 参数 | 默认值 | 单位 / 校验范围 | 运作方式与调节影响 |
| --- | --- | --- | --- |
| `rules.n` | 9 | 整数；2–32 | 总阶数，必须等于 items 长度；合成得到最后一阶即胜利 |
| `rules.m` | 5 | 整数；1–n−1 | 只从 items 的前 m 项随机投放。提高会直接投放更大物体，改变合成节奏和难度 |
| `rules.dropCooldown` | 0.45 | s；0.01–60 | 两次成功投放之间的最短间隔；期间点击/按键不会投放，也不播放放置音效 |
| `rules.mergeCooldown` | 0.12 | s；0.01–60 | 两个物体各自生成后必须都达到此年龄，才能合成；投放物体与合成产物都受此限制。增加会延迟连锁合成 |
| `rules.overflowGrace` | 1.8 | s；0.01–60 | 同一个符合条件的物体连续越线达到该时间即失败；回到线下计时立即清零，不是全场累加 |
| `rules.overflowMaxSpeed` | 1.2 | U/s；0.01–60 | 允许越线计时的最大运动速度，包含平移及旋转边缘速度；移动过快时清零计时，避免下落或弹飞误判 |
| `rules.newbornGrace` | 1.2 | s；0.01–60 | 物体生成年龄超过此值，才允许开始越线计时。合成产物的年龄重新计算 |
| `rules.maxBodies` | 120 | 整数；2–500 | 场上达到此数量后暂时禁止投放，合成减少数量后恢复；数量上限本身不会判负。主要用于性能保护 |
| `rules.keyboardStep` | 0.3 | U；0.01–60 | 每次左右方向键移动的瞄准距离；鼠标和触屏仍按位置瞄准 |
| `rules.avoidRepeat` | true | 布尔值 | 生成“下一个”时尽量避开当前物品；不能保证绝不重复 |
| `rules.repeatRetries` | 6 | 整数；0–32 | 开启 avoidRepeat 时，最多进行这么多次带排除判断的抽取；全都重复后，再抽一次并直接接受。默认最多抽 7 次；0 等同一次独立抽取 |

越线计时要求物体已经超过新生保护期、顶部高于警戒线、运动速度不超过 `overflowMaxSpeed`，并且当前通过下方接触受到容器底部或落地堆叠的支撑。擦到侧壁、空中互碰、空中合成以及弹飞都不算落地；睡眠中的堆叠仍计为有效支撑。只要任一条件不满足，计时立即清零；持续符合全部条件达到 `overflowGrace` 才判负。

| `items[].image` | 非空 PNG 路径；各阶见下表 | 网站模式相对 JSON 文件所在目录解析；例如 `../../assets/stickers/sticker1_remove_edge.png`。导入模式按文件名匹配选中的图片或内置图片 |

### 刚体物理 `physics`

| 参数 | 默认值 | 单位 / 校验范围 | 运作方式与调节影响 |
| --- | --- | --- | --- |
| `physics.unitsPerWorldUnit` | 100 | 内部单位/U；0.0001–1000 | Matter 内部数值尺度，长度、速度、重力等在交界处换算；不改变画面大小。极端改动可能影响引擎内部容差，建议保留 |
| `physics.fixedHz` | 60 | Hz；60–240，建议整数 | 每秒固定物理步数，每步 dt=1/fixedHz；不是显示帧率。提高可细化高速运动和形变求解，但增加 CPU 成本；当前校验不允许降到 30 |
| `physics.maxSubSteps` | 5 | 整数；1–300 | 每个浏览器显示帧最多补算多少个固定物理步；达到上限会清空剩余积累时间。越大越能追赶，但慢设备可能更卡 |
| `physics.maxFrameDelta` | 0.1 | s；0.01–0.5 | 一次显示帧最多接纳的真实时间跨度；长时间卡顿超过这部分直接丢弃，避免瞬间大量追帧 |
| `physics.gravity` | 22 | U/s²；0.0001–1000 | 向下加速度。越大下落、落地冲击越强；不是物体质量，也不直接控制反弹比例 |
| `physics.restitution` | 0.42 | 无量纲；0–1 | 碰撞恢复系数，越大越容易反弹。低于 bounceThreshold 的物体会暂用 0；接触对取双方恢复系数较大值，因此静止物体仍可能被高速来物撞弹 |
| `physics.friction` | 0.35 | 无量纲；0–1 | 动摩擦，越大通常越难沿接触面滑动；接触对取两者较小值。也参与静摩擦的计算，不是空气阻力 |
| `physics.frictionStatic` | 0.9 | 无量纲；0–1 | 静摩擦系数，与动摩擦一起影响“开始滑动”的门槛；接触对取双方较大值。墙使用库的静摩擦默认值，所以把物品此值设很小不等于墙上完全无静摩擦 |
| `physics.airDrag` | 0.012 | 引擎阻力系数；0–1 | 对运动持续施加阻尼，也影响旋转；越大越快慢下来、远距离弹飞越弱。不是每秒固定损失的百分比，Matter 会按步长换算 |
| `physics.density` | 0.001 | Matter 内部密度；0.0001–1000 | 所有物体统一使用，质量约为内部碰撞面积×密度；同密度下更大的实心面积通常更重。统一调高不等于下落更快，且不会改变物体间质量比，通常不是优先手感旋钮 |
| `physics.slop` | 0.004 | U；0–1 | 允许的小幅碰撞穿入容差；太小可能抖动，太大可见重叠。还用于识别凸片间共享顶点/内部边缘。墙体另有库默认容差，接触对取双方较大容差 |
| `physics.positionIterations` | 8 | 整数；1–300 | 每个物理步的位置约束迭代次数；提高通常有利于挤压和堆叠稳定，代价是更多计算，不会直接增加弹力 |
| `physics.velocityIterations` | 6 | 整数；1–300 | 每步速度约束迭代次数，影响接触速度、摩擦与回弹求解；过低可能不稳定，提高会增加成本 |
| `physics.sleepFrames` | 75 | 整数；1–300 | 低运动状态累计多久后休眠，使用 Matter 的基准帧阈值，并按步长调整；在理想持续安静条件下约 75/60=1.25 s，并非任何物体生成后固定 75 帧休眠。越小越早冻结，越大活动时间越长 |
| `physics.maxSpeed` | 22 | U/s；0.0001–1000 | 每步末尾限制物体**平移速度的模长**，合成冲量叠加时也限制；不限制普通碰撞产生的角速度，也不能保证任意高速状态都不穿透 |
| `physics.bounceThreshold` | 1.2 | U/s；0–10 | 低速防抖门槛：以物体平移速度加旋转边缘速度上界判断本步是否开启 restitution。提高可抑制轻碰回弹；这是物体级判断，不是逐接触的相对速度判断 |

`maxFrameDelta` 与 `maxSubSteps` 要一起看：默认每帧至多接纳 0.1 s，但最多补算 5/60≈0.083 s；超额时间会被丢弃。提高 fixedHz 后，如需维持相同追帧能力，也要考虑 maxSubSteps 的预算，而不是一味增大两者。

### 果冻形变 `jelly`

形变不是完整软体模拟。每个物体只有一个局部形变值 s：局部 x 缩放为 exp(s)，y 缩放为 exp(−s)，面积保持不变；图像与实际碰撞箱一起缩放。接触方向决定压扁哪个方向，旋转物体时使用它自身的局部坐标。

| 参数 | 默认值 | 单位 / 校验范围 | 运作方式与调节影响 |
| --- | --- | --- | --- |
| `jelly.enabled` | true | 布尔值 | 是否更新果冻形变；关闭后仍有刚体回弹和合成冲量 |
| `jelly.maxStrain` | 0.2 | 无量纲；0–0.2 | s 的正负幅度上限。0.2 对应一轴最大约伸长 22.1%、另一轴缩短 18.1%，不是简单的两轴各 20%；达到上限会清零形变速度。0 会把积分后的形变夹到 0；要完全关闭形变请用 jelly.enabled=false |
| `jelly.stiffness` | 120 | 弹簧系数；0.000001–1000 | 越大越快把形变拉回当前支撑目标，通常感觉更硬、回弹频率更高；过高需配合阻尼与步长 |
| `jelly.damping` | 8 | 阻尼系数；0.000001–1000 | 抑制形变速度；增大减少振荡，减小会多晃几次。过大也可能显得迟缓，不是“越大恢复越快” |
| `jelly.impactGain` | 0.5 | 冲击增益；0.000001–1000 | 新碰撞按方向向形变速度注入能量，大小约与接触相对法向速度×此值成正比；该速度还受 maxSpeed 截取。越大压缩/拉伸越明显 |
| `jelly.minImpactSpeed` | 1.2 | U/s；0.000001–1000 | 新碰撞达到此相对法向速度才激发一次果冻冲击；提高会忽略更多轻碰。与 physics.bounceThreshold 是两个独立门槛 |
| `jelly.impactCooldown` | 0.22 | s；0.000001–1000 | 同一物体两次新碰撞激发形变的最短间隔；用于抑制重复刺激。不会阻止刚体碰撞或持续支撑压缩 |
| `jelly.restCompression` | 0.012 | 目标形变量；0.000001–1000 | 持续接触时按法线方向形成压缩目标，并对所有接触方向取平均；提高让堆叠状态更扁。它不按承重质量线性增加，也不是静摩擦；通常应明显小于 maxStrain |
| `jelly.settleEpsilon` | 0.001 | 收敛阈值；0.000001–1000 | 形变离目标的差值及形变速度都小于此值时，直接吸附到目标并清零形变速度；提高更快消除尾部微动，但可能感觉突然停止 |
| `jelly.scaleEpsilon` | 0.001 | 形变差阈值；0.000001–1000 | 新形变与已应用形变之差小于此值时，不重建碰撞几何。提高可减少小幅几何更新，但过大会显得一跳一跳；显示始终使用实际已应用的形变 |
| `jelly.restResponse` | 10 | 目标跟随速率（约 1/s）；0.1–60 | 支撑目标按 `1−exp(−restResponse×dt)` 平滑跟随；越大反应越快，越小越柔缓。不是振动频率；默认平滑时间尺度约 0.1 s |
| `jelly.restDeadband` | 0.002 | 目标差阈值；0–0.02 | 支撑压缩目标与当前平滑目标差值不超过此值时不追踪，避免接触法线微变持续挤动；增大更安静，但也可能忽略真实的小形变 |

每步的核心关系是：`形变速度 += [stiffness × (支撑目标 − 形变) − damping × 形变速度] × dt`，随后积分形变并限幅。休眠物体冻结当前形变，唤醒后继续计算。`impactGain`、`impactCooldown` 等名称中的 impact 指物理形变刺激，**不会播放撞击声**；游戏目前只播放放置和合成音效。

当前默认手感参考 [BigNaiWa 的碰撞挤压处理](https://github.com/YHSome/BigNaiWa/blob/main/v1/game.js#L514)：冲击越强，形变越明显，并让刺激衰减。该库使用按碰撞方向的绘制压缩和恢复；这里仍由弹簧驱动实际碰撞形变，降低阻尼后会越过原形、反向回弹，再逐渐停稳。没有额外给整幅画面添加摇晃。

默认单次合成刺激 `strainKick=2` 在没有后续碰撞的测试中，约 0.12 s 达到 10.7% 拉伸，随后反向拉伸约 2.9%，尾部在约 2 s 内收敛；实际接触和堆叠会改变幅度。强碰撞受 maxStrain 限制，最大拉伸约 22.1%。微小接触不激发新冲击，同一物体仍有 0.22 s 触发冷却；持续支撑压缩、低速防弹跳和物理休眠保留。`scaleEpsilon=0.001` 会略过不足约 0.1% 的几何变化，减少尾部更新。更强形变仍可能增加活动堆叠的计算成本，不能保证低性能手机帧率不变。

### 合成冲量 `mergeBurst`

每次成功合成后，对附近其他物体加一次速度增量，不是持续推力，也不直接搬动物体。当前步的合成全部完成后再施加，所以马上被合掉的物体不会重复受力；范围内物体会被唤醒。

| 参数 | 默认值 | 单位 / 校验范围 | 运作方式与调节影响 |
| --- | --- | --- | --- |
| `mergeBurst.enabled` | true | 布尔值 | 开启合成冲量；false 时仍正常合成，但关闭这一套爆发形变和胜利余波模拟 |
| `mergeBurst.rangeMultiplier` | 1.35 | 倍数；0.01–5 | 作用距离中的 size 倍数，size 是**新合成出来**的物品尺寸；越大，高阶合成波及范围增长越明显 |
| `mergeBurst.rangePadding` | 0.7 | U；0–20 | 在 size×rangeMultiplier 之外再加固定距离；使小物品合成也能波及邻近物体 |
| `mergeBurst.speed` | 14 | U/s；0–40 | 基础速度增量，再乘距离衰减和质量系数；最终总速度仍受 physics.maxSpeed 限制。0 会直接跳过整次 burst，包括形变 kick，但 enabled=true 时胜利余波时长仍生效 |
| `mergeBurst.upwardBias` | 1.1 | 方向偏移；0–2 | 从向外的单位方向 y 分量中减去此值，再归一化。0 主要向外，越大越偏向上；不会单独放大速度 |
| `mergeBurst.massExponent` | 0.5 | 指数；0–1 | 质量系数取 `(合成产物质量 / 目标质量)^massExponent`；提高会增强大小物体受影响的差异。0 时质量比项为 1，但仍会经过系数上下限 |
| `mergeBurst.minMassScale` | 0.35 | 倍数；0.01–2 | 质量系数下限；提高会让很重的目标也更容易被弹开 |
| `mergeBurst.maxMassScale` | 1.5 | 倍数；minMassScale–3 | 质量系数上限；降低可防止很轻的目标被弹得过猛 |
| `mergeBurst.spin` | 0.06 | Matter 基准步角速度；0–0.2 | 给受影响物体附加 `向外方向x × spin × 距离衰减` 的角速度，并把结果夹到 ±spin。基准步是 1/60 s，0.06 约对应 3.6 rad/s；只在施加合成冲量时限幅，不是全局旋转上限。**设为 0 会把受影响物体角速度也清零** |
| `mergeBurst.strainKick` | 2 | 形变速度增量；0–2 | 给新产物注入形变刺激，并按方向/距离给邻居注入刺激；只在 jelly.enabled=true 且 burst 实际运行时生效。不是刚体的位移或速度 |
| `mergeBurst.victorySeconds` | 0.8 | s；0–3 | 合成最高阶后继续模拟的余波时间；此时已经胜利且不能投放，时间结束后物理定格，但领奖弹窗和本局画面继续保留，点击“继续游戏”即可保留本局继续游玩。只有 enabled=true 时使用 |

计算概要：

```text
作用距离 R = 新物品 size × rangeMultiplier + rangePadding
距离 d = 合成中心到目标碰撞包围盒最近点的距离
衰减 = 1 − d/R（仅 d < R 的目标受影响）
质量系数 = clamp((产物质量/目标质量)^massExponent, minMassScale, maxMassScale)
速度增量大小 = speed × 衰减 × 质量系数
```

距离使用包围盒最近点，方向使用两个质心的连线再加 upwardBias；因此大图形即使质心较远，也可能被波及。增大冲量或向上偏移后，要同时观察越线宽限时间，避免合成频繁导致失败。

### 碰撞轮廓 `collision`

| 参数 | 默认值 | 单位 / 校验范围 | 运作方式与调节影响 |
| --- | --- | --- | --- |
| `collision.resolution` | 48 | 最长边采样格数；整数 16–128 | 按原图比例缩小 alpha 掩码后提取轮廓；提高更贴图、更能保留细孔，但凸片更多、加载和碰撞开销更大。不是屏幕清晰度 |
| `collision.alphaThreshold` | 16 | alpha 值；1–255，通常用整数 | 像素 alpha ≥ 此值就算实体；同时影响裁透明边距和采样碰撞掩码。提高会排除半透明边缘，也可能改变物品实际包围盒比例和质量。完全不透明的白边仍是实体，不能靠阈值去掉 |
| `collision.simplifyTolerance` | 1 | 采样格；0–1 | 轮廓简化允许的误差；减小更贴近采样边界，凸片通常更多；0 不容许偏离原栅格轮廓。它不是 U，最长边一格约等于 size/resolution U |
| `collision.maxParts` | 96 | 每个物品的凸片数上限；整数 1–256 | 分解超过上限会报错，**不会自动减少片数或降级为圆/矩形**。降低只会更早拒绝复杂图，并不会让同一轮廓自动变省性能 |

凹形、孔洞和独立不透明区域通过多个凸片近似。细于采样格的缝隙可能消失；调轮廓后建议开 debug 查看。图片面积变化还会影响质量、质心和转动惯性，因此换 PNG 也可能改变物理手感。

### 绘制 `rendering`

| 参数 | 默认值 | 单位 / 校验范围 | 运作方式与调节影响 |
| --- | --- | --- | --- |
| `rendering.maxDpr` | 2 | 倍数；1–3 | Canvas 实际 DPR 取设备 DPR 与此值的较小者；提高更清晰，但像素数约随倍率平方增长。降低不改变逻辑大小和碰撞 |
| `rendering.guideDash` | 0.12 | U；0.001–10 | 警戒线和垂直瞄准线的单段实线长度，空白段同样长；提高使虚线更疏 |
| `rendering.lineWidth` | 0.025 | U；0.001–10 | 警戒线线宽，调试碰撞轮廓为其一半；还决定合成粒子半径（2×lineWidth）。垂直瞄准线沿用当前线宽 |
| `rendering.particleCount` | 18 | 个/次合成；整数 0–64 | 每次合成生成的粒子数量，0 关闭粒子。每颗粒子独立随机从新合成图形的可见像素取色，方向、速度大小和寿命也独立随机；默认初始不透明度固定为 90%；允许取到相同颜色 |
| `rendering.particleLifetime` | 1.4 | s；0.001–10 | 随机寿命的上限，实际均匀取自 `[particleLifetime × particleMinLifetimeRatio, particleLifetime]`，默认 0.95–1.4 s。每颗粒子按自己的寿命渐隐，到期删除 |
| `rendering.particleSpeed` | 4 | U/s；0.001–10 | 随机初速度大小的上限；在最小比例到上限间均匀取值，默认 1.4–4 U/s。方向在整圆内独立随机，再由重力形成抛物线；不影响 mergeBurst |
| `rendering.particleMinSpeedRatio` | 0.35 | 比例；0–1 | 最小初速度大小 / particleSpeed；设为 1 固定速度大小，但方向仍随机 |
| `rendering.particleMinLifetimeRatio` | 0.6785714285714286 | 比例；0.01–1 | 最短寿命 / particleLifetime；设为 1 固定寿命 |
| `rendering.particleOpacityMin` | 0.9 | 不透明度；0–1 | 初始不透明度下限；0 全透明、1 完全不透明。默认与上限相同，使每颗粒子的初始不透明度固定为 90% |
| `rendering.particleOpacityMax` | 0.9 | 不透明度；particleOpacityMin–1 | 初始不透明度上限；上下限不同时才会产生随机变化。显示时再乘以 `1 − 年龄/寿命`，所以会逐渐淡化而不是突然消失 |
| `rendering.particleGravity` | 8 | U/s²；0–1000 | 粒子的独立向下加速度；0 为匀速直线运动。不会对物体施力，也不会随已明确设置的 physics.gravity 自动变化 |
| `rendering.maxParticles` | 512 | 同时存活数量；整数 1–4096 | 连锁合成时的粒子总数上限，超出后移除最早生成的粒子，避免持续增加绘制开销 |

每张 PNG 加载时，从 alpha 达到 collision.alphaThreshold 的原始像素中均匀抽样，缓存最多 512 个颜色样本；每颗粒子再独立、有放回地随机选取一个样本。缓存只保存真实像素的 RGB，不按主题色染色，也不在每次合成或绘制时重新读图。

粒子仅存在于渲染器，不创建物理刚体：会穿过物体、其它粒子和容器边界，离开画布的部分自然不可见，不发生碰撞、反弹或相互作用。暂停时运动和寿命同时暂停，重开清空粒子。系统“减少动态效果”开启时不生成装饰粒子。

### 旧配置兼容与音效边界

- 缺少 `rules.overflowMaxSpeed` 时补 1.2。
- 缺少 `rules.avoidRepeat` 时补 `false`；缺少 `rules.repeatRetries` 时补 6。
- 缺少整个 `mergeBurst` 对象时，会补一套 **enabled=false** 的兼容配置，因此旧皮肤没有合成冲量；如果已经有该对象，需填写完整子字段。
- 缺少 `physics.bounceThreshold`、`jelly.restResponse`、`jelly.restDeadband` 时，分别补 1.2、10、0.002。
- 旧配置缺少新增粒子字段时，最短寿命比例补 0.5、最小速度比例补 0.35、不透明度范围补 0.45–0.75、数量上限补 512；缺少粒子重力时按该配置的 physics.gravity 补齐。
- 其他必需字段不要依赖自动补全；以当前完整 JSON 为模板修改最可靠。
- 音效路径、音量、合成随机升调不在此 JSON 中，而在 `src/merge/audio.js` 的 `AUDIO` 常量中。当前没有撞击声及其触发/限频/能量计算逻辑。
- 修改配置后按前面的“皮肤与参数”流程修改配置，并运行 `python scripts/package_merge.py` 更新双击默认数据。仅编辑 JSON 后直接重新双击 HTML，不会自动采用尚未打包的新默认值。

碰撞形状来自 alpha 通道，不是 PNG 矩形，也不是简单圆形或整个物体的凸包。凹形、孔洞、独立的不透明区域会分解为凸片。为控制移动端成本，它是**采样后的轮廓近似**：默认最长边采样 48 格，允许 1 格轮廓简化误差；比采样格更细的透明缝隙/细节可能消失。轮廓过复杂会明确报错，不会默默替换成矩形。更精细的皮肤可提高分辨率、降低误差，但计算量会增加。`?debug=1` 可显示实际碰撞轮廓：粉色为活动，蓝色为休眠。

果冻使用一个受限、带阻尼的局部拉伸/压缩自由度，并以互为倒数的两轴缩放保持面积。它会同步改变实际碰撞几何，因此能推挤相邻物体；这是轻量近似，不是完整软体网格。冲击按方向激发形变，持续接触保留小幅压缩。休眠后冻结形变，微小碰撞不重复激发回弹；合成在物理更新后统一处理，一个物体每步最多参与一次合成。

合成成功时从 `assets/merge/pop.mp3` 和 `assets/merge/pop2.mp3` 中随机播放一个，各 50% 概率，允许连续重复。每次合成再独立以 50% 概率升高 3 个半音，其余保持原调；升调时声音也会稍短。`pop2.mp3` 只保留开头一声气泡破裂及自然尾音（约 0.15 秒）。

成功投放图形时播放 `assets/merge/drop-soft.wav`：约 0.135 秒的柔和短音，音高从 280 Hz 轻轻下降至接近 190 Hz，以 8 毫秒柔和起音、快速衰减。该音效由 `python scripts/synthesize_drop.py` 使用标准库生成，合成参数在脚本的 `SETTINGS` 中，游戏运行无需 Python。旧 press 素材保留，但不再加载或打包。投放保持原调，冷却期间的无效操作不会出声；归一化后使用 `dropVolume: 1`，不再额外减半音量，使响度接近合成音效；仍用 `dropLowpassHz: 1600` 柔化高频，只在加载时处理。

`audio.js` 独立订阅 `drop`、`merge` 事件。页面加载时预先解码，首次点击、触摸结束或按键解锁音频；首个事件最多等待本次解锁 150 毫秒，重开或隐藏页面取消等待。每段音频只解码一次，自动裁掉前导空白、保留 4 毫秒起音余量并做 2 毫秒淡入，再按最响的 50 毫秒窗口 RMS 匹配主体音量（目标 0.2，设有增益及峰值上限）。总共最多叠加 4 个声音。音效列表、音量、升调与响度参数均在 `AUDIO` 中调整。加载失败不影响游戏，重开或切换皮肤停止旧声音。双击版本内嵌三段音频，替换素材后运行 `python scripts/package_merge.py` 更新。

性能措施：图片和碰撞轮廓只加载一次；背景点阵按当前画布分辨率缓存，每帧一次绘制，窗口尺寸/DPR 改变时重建；物体未形变时的包围半径预计算；碰撞前速度快照复用，合成/重开/销毁时释放；避免绘制中的临时数组和投放后重复刷新界面。另有凸片合并、物理休眠、固定步长、最大追帧数、速度上限、最大物体数、DPR 上限。后台暂停避免回来后累积大量物理帧。系统“减少动态效果”设置关闭装饰粒子，物理规则保持一致。

## 开发与验证（游玩不需要这些工具）

保留分模块的源码以方便维护，`game.js` 是双击入口使用的普通脚本。修改 `src/merge/` 源模块后，运行下面的标准库脚本重新打包；不要手工编辑生成的 `game.js` 或 `offline-data.js`。该脚本只处理本项目明确使用的命名导入/导出语法，不是通用 JavaScript 编译器。

```sh
python scripts/package_merge.py          # 重新生成脚本与离线皮肤数据
python scripts/package_merge.py --check  # 检查生成文件是否与源码一致
python scripts/check.py                 # 打包一致性、Python/Node 测试；无需 npm install
node --test tests/*.test.js              # 只运行 Node 内置测试
```

`package.json` 只用于声明源码为 ES modules，没有 dependencies、devDependencies 或启动服务脚本。普通网页入口使用预生成的经典脚本，不受 file:// 的 ES module 限制。JSDoc 和本地类型声明支持编辑器检查；没有类型包下载要求。

测试按职责拆分为配置、几何、物理、粒子、音效和离线打包；共享配置/世界构造放在 `tests/helpers/`。`scripts/check.py` 使用 Python 标准库和 Node 内置测试器，不下载任何依赖；如果本机已有 `node_modules/typescript/bin/tsc`，还会检查 JSDoc 类型，否则明确跳过类型检查。

可选浏览器回归脚本为 `tests/browser/merge.smoke.mjs`：开发环境已经安装 Playwright 和 Edge 时，运行 `node tests/browser/merge.smoke.mjs`。其他 Chromium 浏览器可用 `BROWSER_EXECUTABLE` 指定可执行文件。它直接打开 file://，分别检查桌面键盘/手机触摸、离线音效、精简界面、暂停重开、九阶合成领奖和无 HTTP 请求，不启动服务器。这些开发工具不是游戏运行依赖。另可运行 `node tests/browser/loading.smoke.mjs`，用浏览器请求拦截模拟在线访问、图片首次失败及音频断网恢复，检查在线不下载离线包，无需启动服务器。
